# Grid Pulse — static report

A standalone, static HTML/CSS/JS report showcasing the project's data and
model results in an editorial "scrollytelling" style — separate from the
live Streamlit tool. Built with plain HTML/CSS, [Chart.js](https://www.chartjs.org/)
for charts, and [Leaflet](https://leafletjs.com/) for the map. No build step,
no framework, no server required to run it.

## What's in here

```
report/
├── index.html   -- page structure, all section copy
├── style.css    -- dark editorial theme (same fonts/accent as the Streamlit app)
├── app.js       -- renders charts/map/tables, count-up stats, scroll-spy nav
├── data.js      -- REAL project data, embedded as a JS object (see below)
└── data/
    └── report_data.json  -- the same data, as plain JSON (source of truth)
```

**All the numbers in this report are real**, pulled directly from your
engineered dataset (`data/processed/`) and the trained model's saved metrics
(`models/demand_model_metrics.json` / `demand_model_importance.json`) at the
time `data.js` was generated. Nothing here is placeholder text.

If you retrain the model or the underlying data changes, regenerate
`data.js` by re-running the extraction (ask me, or see the "Regenerating
the data" section below) — it won't update itself.

## Running it locally

No build step needed. Because `data.js` embeds the data as a plain JS
variable (not fetched via `fetch()`), you can even open `index.html`
directly in a browser via `file://` and it'll work. For a closer-to-production
test, serve it locally:

```bash
cd report
python -m http.server 8000
# open http://localhost:8000
```

## Deploying to Vercel (matches the reference site's setup)

1. Push this `report/` folder to a GitHub repo (can be the whole project repo —
   Vercel lets you set a subdirectory as the project root).
2. Go to [vercel.com](https://vercel.com) → **Add New Project** → import the repo.
3. When configuring, set **Root Directory** to `report` (if it's a subfolder
   of a bigger repo).
4. Framework preset: **Other** (it's static HTML, no framework to detect).
5. Leave build command blank, output directory blank — Vercel will serve
   the files as-is.
6. Deploy. You'll get a `*.vercel.app` URL, same as the reference project.

## Deploying to Netlify or GitHub Pages (equally simple alternatives)

- **Netlify**: drag-and-drop the `report/` folder onto
  [app.netlify.com/drop](https://app.netlify.com/drop) — no repo needed for
  a quick deploy, or connect the repo the same way as Vercel.
- **GitHub Pages**: push `report/` to a repo, enable Pages in repo Settings
  → Pages, pointing at the branch/folder. You'll get a
  `yourusername.github.io/reponame` URL.

All three are free for a static site like this.

## Linking the live Streamlit app

`app.js` has a placeholder for the "Open live tool →" button in the sidebar:

```js
const liveLink = document.getElementById('live-app-link');
if (liveLink) liveLink.href = 'https://your-streamlit-app-url-here';
```

Once your Streamlit app is deployed (Streamlit Community Cloud / Hugging
Face Spaces / Render — not Vercel, which can't run Streamlit), update that
URL in `app.js`.

## Regenerating the data

`data.js` was generated by aggregating `data/processed/*.csv.gz` and reading
`models/demand_model_metrics.json` + `demand_model_importance.json` into
`report/data/report_data.json`, then wrapping it as `const REPORT_DATA = {...}`.
If you retrain the model or refresh the data, re-run that extraction (the
aggregation script isn't currently saved as a standalone file in this repo —
ask me to add one as `src/03_build_report_data.py` if you want to automate
this step).

## Honest limitations

- This gets close to the reference site's *aesthetic* (same font stack, dark
  theme, kicker labels, scroll-spy nav, section rhythm) but the reference
  site's own bespoke layout details (its exact card treatments, any custom
  scroll-triggered animations beyond the count-up here) weren't reverse
  engineered line-by-line — this was built to the same *spirit*, not pixel-cloned.
- Charts/map require internet access to load Chart.js and Leaflet from CDN
  (jsdelivr / unpkg). If you need a fully offline version, download those
  libraries into `report/vendor/` and update the `<script>`/`<link>` tags
  in `index.html` to point locally.
- I validated this by running it in a headless browser: confirmed the
  count-up stats, all 5 charts (with correct data), the Leaflet map (all
  276 feeder markers), the scroll-spy nav, and the best/worst tables all
  execute without JavaScript errors. Because this sandbox has no internet
  access, I could not verify the actual visual rendering of Chart.js charts
  or Leaflet tiles/markers (only that the correct API calls with correct
  data are made) — give it a visual check once deployed.
